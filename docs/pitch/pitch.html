09 / 14
Q

What about breaking changes?

A

Caught before merge. Semantically, not textually.

v1.yaml — current prod
  Pet:
    required:
      - id
      - name
    properties:
      id:     integer
      name:   string
      status: string
v2.yaml — proposed
  Pet:
    required:
      - id
-     - name
+     - species
    properties:
      id:      integer
-      name:    string
+      species: string
⊘ 2 breaking changes · required field name removed · new required field species added

Semantic = understands OpenAPI. Textual diff tools would show 4 lines changed; the compatibility engine shows which ones actually break clients.

10 / 14
Q

Isn't PACT the same thing?

A

Same goal. Opposite direction.

PACT
Test-first.
Mock-recorded.

Consumer writes tests against a PACT mock DSL. Interactions get recorded into a pact file. Producer replays those recordings and must match every one.

CVT
Schema-first.
Spec-pinned.

Producer publishes OpenAPI. Consumer pins a version. Both sides validate real traffic against the schema. No mocks to drift, no recordings to regenerate.

Key framing: PACT is bottom-up (from consumer code). CVT is top-down (from the spec). Same outcome — opposite mental model.

Q

How do I start?

A

Three commands.

getting started
# 1. install
$ brew install sahina/tap/cvt
or: curl -L github.com/sahina/cvt/releases/latest/download/cvt-darwin-arm64 -o cvt
 
# 2. register your spec
$ cvt register-schema my-api ./openapi.yaml
→ registered my-api@1.0.0
 
# 3. gate your deploys
$ cvt can-i-deploy --schema my-api --version 2.0.0 --env prod
PASS — ship it

Point out: no Docker required for step 1. Local mode is first-class. Server is opt-in for teams that want central registry + deploy gates.
